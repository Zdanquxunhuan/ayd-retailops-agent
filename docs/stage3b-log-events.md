# Stage 3B 日志事件取证 v2

本轮把 logs.search 从同一行关键词提升为时间戳事件、异常堆栈与明确 trace 关联。美团仍模拟，不需要 AppKey；本地订单和 POS 仍模拟，不代表已完成所有 Stage 3B 接入。

## 调用与模型职责

启动方式沿用 stage3b-log-snapshots.md。模型仍只传 storeId/orderId，日期和目录由服务端配置。Java 负责扫描、事件划分、关联、脱敏和边界；模型读取 diagnostics 中的错误描述与堆栈，结合其他证据提出假设并选择下一次查询。未知异常类和错误消息可进入模型，不预设封闭根因清单。

日志文本是不可信数据，prompt 明确禁止执行其中的指令。新增代码不连接服务器，也不执行 shell。真实模型验证需要本地配置模型凭据；脚本规划器的测试只能验证契约，不能证明大模型诊断质量。

## 事件和关联

- 时间戳开头的新行开启事件，后续异常及堆栈归入该事件，直至下一个时间戳。
- ORDER_ID：事件包含精确匹配的目标单号；显式其他订单字段会拒绝混合事件。
- TRACE_ID：在同一文件内完整事件明确绑定目标单号和 traceId，其他事件可按该 trace 关联，支持异常先于绑定事件出现。
- traceId 格式为 traceId=xxx 或 traceId:xxx。出现其他订单绑定或截断绑定时，废弃该 trace 的间接关联。
- 不根据线程名称或时间临近自动串联；无单号、无明确 trace 的异常不能自动归到目标订单。暂不做跨文件 trace 关联。

返回 lines 中每项含 file、lineStart、lineEnd、eventTime、correlation、eventComplete、signals 和 diagnostics。时间来自日志，按原始本地时间返回，不伪造时区。observedAt 仍是读取时间。

## 截断与证据规则

单行最多保留32768字符，超长内容丢弃到行末后继续。单事件最多8192字符；每文件最多10000事件；全调用最多2000万解压字符、8文件、10命中，5秒执行时间。目录最多检查1000项。

scanTruncated 表示扫描或内容存在限制；complete=false 表示副本不能代表整个业务链路。一个局部扫描中保留的完整、明确关联事件可以用于带限定语的正向历史假设；空结果和截断事件不能支撑根因。引用是工具 Evidence ID，正文可附文件与行号。若同一 Evidence 含截断事件，保守地不允许将它作为决定性证据。

查询不会因为截断变成 NOT_FOUND，不能从未命中推导美团未推送。日志中的“推送成功”也不能代替当前 POS 查询。

## 脱敏范围

只返回异常行和 Java 堆栈帧，最多8行，每行220字符；普通订单报文不返回。敏感字段、SQL、JSON 或 payload 标记触发详细信息移除；引号值、URL/JDBC、邮箱、IP、长数字及键值被替换。异常类名和剩余消息用于模型理解。

这是针对当前日志格式的规则投影，不是通用个人信息识别器；未带字段标签的姓名或自由文本仍可能漏检。使用真实外部模型前，应使用经人工确认脱敏的日志副本。不要把含客户原文的日志纳入 GitHub。测试全部使用合成数据。

## 验证与下一步

测试覆盖超长行后的事件可见性、跨行堆栈、明确 trace 前后关联、冲突 trace、线程复用隔离、敏感字段、未知错误描述、预算截断，以及部分扫描中完整事件的证据校验。保留原有美团模拟场景回归。

真实模型无凭据时不执行在线调用。后续可用同一套脱敏案例，验证模型引用、未知原因处理和下一步查询选择；本地订单/POS 查询适配仍待接入。
