# Stage 1D：证据驱动的假设修正

日期：2026-11-11。已实现核心契约、运行时校验、Prompt 和报告更新；业务数据仍为模拟。真实模型实测 7 次请求，4 次运行未完整通过，详见 [实测记录](stage1d-live-verification.md)。本阶段关注模型如何使用新证据修正判断，不增加写操作。

## 模型现在需要完成的工作

每个假设补充四项字段：

|字段|含义|
|---|---|
|temporalScope|CURRENT 当前状态，或 HISTORICAL 历史事件|
|timeWindow|命题对应的时段；不清楚时明确未知，不补造日期|
|proposition|POS_ABSENT、POS_PRESENT 或 OTHER 原因命题|
|falsificationCriterion|什么观察可以推翻这个假设|

同一个假设 ID 的命题、时段和可推翻条件不能被换掉。若模型想讨论不同时间或不同原因，应建立新假设。

每轮上下文提供 `newEvidenceIds`，只包含上次接受决策之后增加的观察。模型对所有旧假设逐项输出 `reviews`，说明 MAINTAIN（维持）、REVISE（修改）或 INSUFFICIENT（证据不足）。每条复核都必须考虑本轮全部新证据，可说明某条观察为什么与该时段的命题无关；这不等同把全部观察当支持证据。

模型仍负责理解日志、提出原因、判断语义关联及选择工具。Java 只检查复核完整性和已明确建模的事实约束，不替模型自动写调查解释。

## 已实施的约束

- 漏掉任何旧假设或新增观察，拒绝本轮提议。
- 复核说“维持”却修改假设，或说“修改”却没有修改，拒绝。
- 选择“证据不足”时，假设须为 UNCONFIRMED，并保留待补证据。
- CURRENT/POS_ABSENT 遇到最新完整 FOUND，必须改为 CONTRADICTED，并引用该反证；POS_PRESENT 遇到 ABSENT 同理。
- 当前 POS 状态不能单独支持或反驳 HISTORICAL 假设，须有对应历史来源；空历史记录仍不能充当支持或反证。
- 未通过校验的更新和查询不会执行，保留原假设及被拒绝的提议。对漏复核、非法查询结构、缺少 POS 复查三类错误，每个任务最多反馈一次明确错误让模型重写；仍扣请求预算，再失败就转人工。越权等其他错误直接停止，不自动修正文案或切换规则 Stub。

例如“当前尚未落库”被最新 POS FOUND 推翻；“此前存在落库延迟”仍可能未知。这两个命题不能混在一个假设中。

## 运行与观察

命令与 API 沿用 Stage 1C：

```powershell
.\scripts\stage1.ps1 build
.\scripts\stage1.ps1 investigate -Provider qwen -Fixture investigation-reversal -MaxRequests 6
```

真实调用需要进程环境中的 DASHSCOPE_API_KEY 和足够的已授权请求额度；上述命令本身不代表新增授权。零模型状态检查仍可用 `-Provider stub -Fixture synced -Intent CHECK_STATUS`。

当前新任务版本为 `order-investigation-v5` / `investigation-v2`。此前 Prompt 文件和实测报告保留。旧快照可读取，不自动补造时间字段；恢复策略仍是中断任务转人工，不会用新契约续跑旧调查。

`report.md` 新增“假设时间范围与反驳条件”和“每轮旧假设复核”表。`trace.json` 保存每轮 reviews，包含被拒绝的提议；`reviewedEvidenceIds` 只在接受决策后推进。

## 验证与边界

JDK 17 构建成功，65 项测试通过，见 `.build-cache/stage1d-v5-build.log`。新增回归检查覆盖漏审、忽略新证据、当前与历史混淆、修改时段逃避反证、复核与更新不一致、旧 JSON 兼容及一次纠正的边界。既有多轮循环、落盘、权限、预算、取消和模型失败测试继续通过。

这些是程序约束测试，测试替身不是大模型。本轮真实模型调查未完整通过，且尚未观察到真实模型利用纠正反馈成功完成调查；不能把离线测试算作模型通过。

OTHER 自然语言命题的语义、模型是否正确分类命题、历史证据是否真的属于所声明时段，以及报告文字的因果关系，仍不能靠结构校验完全保证。模型也可能把本该归类为 POS 状态的命题错误标成 OTHER；这种情况需要后续人工评分和语义评估。当前实现不声称已解决所有因果推断问题。
